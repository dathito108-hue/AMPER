# Phase663 — M5 Proactive Attention / Approval Discoverability

Phase663 adds a bounded Android attention surface for durable proactive work without adding a second
planner, scheduler, approval mechanism, task database, ToolFabric, AuthorityGate, model path, or
execution port.

The canonical execution chain remains:

```
Phase658 bounded trigger source
  -> Phase659/660 encrypted source record + accepted-observation FIFO
  -> Phase661 deterministic canonical persistent-plan binding
  -> Phase662 immutable lifecycle provenance + canonical plan-derived state
  -> Phase655 verified EVENT_WAKE handoff
  -> Phase657 Android EVENT_WAKE scheduler
  -> Phase656 one-step canonical consumer
```

Phase663 is discoverability only. It observes this chain and surfaces user attention where useful.

## Attention policy

`AmperAgentProactiveAttentionPolicy` derives attention only from the Phase662 lifecycle view:

- `WAITING_APPROVAL` -> `APPROVAL_REQUIRED`;
- completed plan -> `COMPLETED`;
- failed/cancelled plan -> `FAILED`;
- tracked provenance with a missing canonical plan -> `PLAN_UNAVAILABLE`;
- runnable/checkpointed/non-terminal work -> `NONE`.

It cannot mutate a plan, approve/reject a tool action, create a plan, schedule a wake, or execute a
tool.

Terminal completion/failure notifications are emitted only when observed as a background transition.
Foreground reconciliation does not replay historical terminal notifications. Approval-required and
missing-plan attention remain discoverable during foreground reconciliation because both need explicit
user review.

## Android notification surface

`AndroidAgentProactiveAttentionController` is attached to the existing
`AndroidCanonicalAgentRuntimeGraph`.

It owns one notification channel, permission/settings inspection, stable notification identity,
best-effort post/cancel/reconciliation, and navigation to the exact tracked canonical proactive plan.
It owns no JobService and no scheduler.

`POST_NOTIFICATIONS` is requested only from the foreground lifecycle panel when Android requires the
runtime permission. Denied permission, disabled app notifications, disabled channel, or notification
delivery failure does not change plan state, EVENT_WAKE state, source FIFO state, or execution
outcome.

## Privacy-preserving copy

Notification text is generated by
`AndroidAgentProactiveAttentionNotificationCopyPolicy`.

Its API accepts only the attention kind and bounded waiting approval step index. It intentionally
accepts no goal, source id, trigger payload, tool input, plan contents, or user prompt. Notification
copy is therefore generic and bounded.

The notification may carry the canonical deterministic plan id only as internal navigation identity;
it is not rendered in title/body text.

## Stable identity and navigation

Each notification uses the full canonical deterministic proactive `PlanId` as its Android
notification tag:

```
amper.proactive.plan:agent-trigger-plan:<64 lowercase hex>
```

The numeric notification id is constant while the tag remains plan-specific, so separate proactive
plans do not collapse into one notification identity.

The notification `PendingIntent` is explicit and immutable. The plan extra is accepted by
`MainActivity` only when it matches exactly:

```
agent-trigger-plan:<64 lowercase hex>
```

Uppercase, short, non-proactive, or suffixed ids are rejected. Tapping a notification opens the same
Phase662 lifecycle-tracked canonical plan. It does not approve anything directly.

## Non-gating sequencing

Phase661 dispatch keeps its durable ordering:

```
1. persist immutable lifecycle provenance
2. install/cancel the verified Phase657 EVENT_WAKE
3. best-effort Phase663 attention sync
4. acknowledge the Phase660 accepted-observation FIFO
```

The attention step is best effort. A notification exception cannot prevent FIFO acknowledgement after
the durable canonical binding and verified scheduler disposition already succeeded.

After Phase656 EVENT_WAKE execution, Phase657 asks the same canonical attention controller to surface
the resulting lifecycle state. This remains best effort and cannot alter the host execution result or
checkpoint chaining.

Foreground approval/rejection/cancellation continues through the existing governed plan surface.
After that canonical mutation, Phase662 re-arms/cancels Phase657 as before and Phase663 only refreshes
the attention surface.

## Architecture locks

Phase663 adds:

- `proactive-attention-is-lifecycle-derived-discoverability-only`
- `proactive-attention-never-approves-schedules-or-executes`
- `proactive-notification-copy-excludes-goal-source-payload-and-tool-input`
- `proactive-notification-navigation-validates-full-canonical-plan-id`
- `proactive-attention-failure-never-gates-event-wake-or-trigger-fifo-ack`
- `proactive-terminal-attention-surfaces-only-on-background-transition`

The M5 exit criteria now also require lifecycle-only attention ownership, bounded privacy-preserving
notification copy, exact canonical plan navigation with no direct approval action, background-only
terminal surfacing, and notification failures that cannot gate Phase657 execution or Phase660 FIFO
acknowledgement.
